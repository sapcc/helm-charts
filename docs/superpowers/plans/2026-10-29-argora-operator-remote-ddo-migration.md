# argora-operator-remote → DDO Migration — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate `argora-operator-remote` on the m-qa-de-200 Metal-API cluster from the legacy GRM/Helm-release model to a dual-deployment-operator (DDO)-managed operand chart, with CR delivery via kube-secrets and a cutover profile for the generalized toolkit.

**Architecture:** A thin operand chart `system/argora-operator-remote-ddo` wraps the upstream `argora` subchart (same pin) and adds mode-guarded sapcc templates (seed: remote-kubeconfig Secret; shoot: the 3 data CRs). DDO renders it twice — seed render → a-qa-de-200 (controller, credentials Secret), shoot render → m-qa-de-200 (CRDs, RBAC, data CRs). Per-cluster config + vault credentials move into the operand chart values and the DDO CR; a `filterKinds` transformation prunes the upstream credentials Secret + metrics Service from the shoot render. Cutover reuses the generalized toolkit with a new argora profile plus a `PROTECT_MRS` gate (the data-CR MRs lack `keepObjects`).

**Tech Stack:** Helm 3, dual-deployment-operator CRD, Gardener ManagedResources/token-requestor, kube-secrets helm-chart-pipeline, bash (cutover toolkit), u8s/kubectl.

**Spec:** `docs/superpowers/specs/2026-10-28-argora-operator-remote-ddo-migration-design.md`

## Global Constraints

- **The operand chart MUST NOT set `.Values.mode`** — DDO injects it; a `mode` default makes the operator reject the render. (CI `no-mode-default.sh` enforces.)
- **Subchart pin:** `argora 0.0.1-20261023094418-9e2ccc2-crds` from `oci://ghcr.io/sapcc/charts`, alias `argora-operator-core` — identical to the legacy chart's Chart.lock.
- **`argora-operator-core.fullnameOverride: argora-operator`** — load-bearing: makes the shoot render's SA/CRB/CR names byte-identical to the live legacy shoot bundle (SA `argora-operator-controller-manager`, ClusterRole `argora-operator-manager-role`, CRB `argora-operator-manager-rolebinding`) and match the token-requestor kubeconfig identity.
- **Chart version = clean semver**, start `0.1.0` (a `_sha` suffix → "improper constraint" → SeedRenderFailed).
- **`charts/*.tgz` is gitignored** (root `.gitignore` `*.tgz`); commit only `Chart.lock`.
- **Images:** operand chart defaults to GHCR (`ghcr.io/sapcc/argora`); the keppel mirror override (`keppel.global.cloud.sap/ccloud-ghcr-io-mirror/sapcc/argora`) lives in kube-secrets.
- **Vault credentials never in the DDO CR** (admin-k3s helm-diff secrets-injector-validator forbids vault refs in non-Secret kinds); they live in the operand chart `values.yaml` under `argora-operator-core.credentials` with `${REGION}` + `replace` substitution (NOT `tpl`).
- **shootNamespace: `kube-system`**; **applyOrder: SeedFirst**.
- **Data-CR templates pass arbitrary `.spec` through verbatim** (`range` + `toYaml`), never model the qa-de-200 shape — prod regions use richer specs (`namePrefix`/`role`/`region`).
- **PR hygiene:** ONE feature branch per repo → ONE PR to master. helm-charts branch `feat/argora-operator-remote-ddo-m-qa-de-200` (already created, has the design + this plan). kube-secrets its own branch. Publish the operand chart to keppel BEFORE the kube-secrets CR referencing it merges.
- **CODEOWNERS:** `/system/argora-operator-remote-ddo` = `@sapcc/PlusOne-CE-API-Services-ControlPlane @sapcc/baremetal` (match legacy `/system/argora-operator-remote`).

## Review Focus

- **Credentials leaking to the shoot** — the subchart's `extras/secret.yaml` renders on BOTH renders (no mode guard); without the `filterKinds:[Secret]` transformation the BMC/netbox credentials Secret lands on m-qa-de-200. Task 7's CR transformation + Task 8's render-inventory check pin this.
- **Shoot SA/CRB identity drift** — if `fullnameOverride` is wrong the controller's token-requestor identity (`argora-operator-controller-manager`) no longer matches the shoot CRB subject → the controller loses shoot access. Task 2 values + Task 8 shoot-inventory diff pin this.
- **Data-CR deletion on uninstall** — the 3 data-CR MRs lack `keepObjects`; a naive uninstall deletes the live CRs (incl. the IPPoolImport backing an allocated GlobalInClusterIPPool). Task 9's `PROTECT_MRS` gate pins this.
- **Mode default creeping into values.yaml** — any `mode:` key makes DDO reject the render. Task 6 CI `no-mode-default.sh` pins this.
- **Seed pod missing its mandatory credentials Secret** — the manager always mounts `<fullname>-secret`; if the seed render omits it (wrong subchart flags) the pod won't start. Task 2 values (manager.enable seed) + Task 8 seed-inventory check pin this.
